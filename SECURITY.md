# Security reports

Do not post credentials, private data, connection URLs or exploitable vulnerability details in a public issue.

Use GitHub's **Security → Report a vulnerability** private reporting option for this repository if it is enabled. If it is unavailable, open a short issue asking maintainers for a private reporting channel, without including the vulnerability details or sensitive evidence. This project does not promise a response deadline.

A useful private report includes the affected version, DSH/Node versions, the access an attacker needs, a minimal synthetic reproduction, expected and observed behavior, and the impact. Remove real credentials and private rows. Do not upload a full state database or conversation unless a private channel and scope have been agreed.

The maintained target is the 0.1 release. Do not use older development builds against a newer state directory. See [maintenance](docs/install-and-maintain.md) and [data/privacy boundaries](docs/data-and-privacy.md).

## 中文

不要在公开 issue 中发布密钥、连接 URL、私有数据或可直接利用的漏洞细节。若仓库已启用 GitHub「Security → Report a vulnerability」，请使用私密报告；否则只发一条不包含敏感细节的 issue，请维护者提供私密渠道。本项目不承诺响应时限。

报告注明版本、必要权限、合成数据最小复现、预期 / 实际行为与影响。未约定私密渠道和范围前，不要上传完整状态库或聊天记录。
